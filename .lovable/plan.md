# Static pre-rendering for blog + marketing routes

Goal: when the site builds, every public route is written to disk as a fully rendered HTML file with its correct per-page title, meta description, canonical, Open Graph, Twitter Card, and JSON-LD tags. Non-JS crawlers (LinkedIn, Slack, Discord, Facebook, iMessage) will then read the correct preview for each blog post instead of the sitewide fallback.

## Approach

Use `react-snap` — the standard tool for pre-rendering client-rendered React SPAs. It runs after `vite build`, launches a headless Chromium, visits every route locally, waits for the app (and `react-helmet-async`) to render, and writes each route to `dist/<path>/index.html`. Lovable's static hosting already serves those files at their paths, so no server-side runtime is added.

## Changes

1. **Add dev dependency**: `react-snap`.
2. **`package.json`**:
   - Add `"postbuild": "react-snap"` so it runs automatically after `vite build`.
   - Add a `reactSnap` config block:
     - `source: "dist"`
     - `include`: `["/"]` plus every marketing route and every `/blog/<slug>` derived from `src/data/blogPosts.ts` (generated by a small script at build time — see technical section).
     - `puppeteerArgs: ["--no-sandbox", "--disable-setuid-sandbox"]` for the sandbox environment.
     - `inlineCss: false` (keeps existing Vite CSS chunking).
3. **`src/main.tsx`**: switch from `createRoot(...).render(...)` to `hydrateRoot(...)` when the root already has children (react-snap's pre-rendered output), and fall back to `createRoot` otherwise. Standard react-snap pattern.
4. **`scripts/generate-prerender-routes.ts`**: small tsx script that reads `blogPosts.ts` + the static route list and writes the include array into a JSON file (`.prerender-routes.json`) that `package.json`'s `reactSnap.include` reads. Wired into `prebuild` so the list is always current.
5. **No component changes** — `Seo.tsx` already emits all the tags; react-snap captures them into the static HTML.

## Verification

- After build, confirm `dist/blog/iam-vendors-purchasing-power-parity-pricing/index.html` exists and contains the correct `<title>`, `og:image`, and JSON-LD.
- After the next republish, `curl` the live URL and grep for `og:title` — the value should match the post title, not the sitewide fallback.

## Risk / mitigation

- **Build time increase**: adds ~30–90s for 51 posts + marketing pages. Acceptable trade for correct social previews.
- **Puppeteer Chromium download**: react-snap installs its own Chromium. If the deploy environment blocks this, we fall back to `@prerenderer/rollup-plugin` with the same route list. I will confirm the build succeeds before considering this done.
- **Hydration mismatches**: any component that renders differently on first paint (e.g., reads `window`) can warn. If any surface, they're localized fixes to guard with `typeof window !== "undefined"`.
- **No changes to routing, data, or Cloud/backend** — SPA behavior after hydration is unchanged.

## Technical detail

- `scripts/generate-prerender-routes.ts` uses `tsx` (already available via bun/npx) to import `src/data/blogPosts.ts` and emit `.prerender-routes.json` with entries like `["/", "/about", "/services", "/blog", "/blog/iam-vendors-purchasing-power-parity-pricing", ...]`.
- `package.json` `reactSnap.include` is populated from that JSON via a `"reactSnap": { "include": [...] }` block regenerated pre-build. Because `package.json` cannot reference external JSON at parse time, the script writes the include list directly into `package.json` between two sentinel comments in a `reactSnap` field.
- `hydrateRoot` guard in `main.tsx`:
  ```
  const root = document.getElementById("root")!;
  root.hasChildNodes() ? hydrateRoot(root, <App/>) : createRoot(root).render(<App/>);
  ```
- Routes with dynamic 404 behavior (`/not-found`, catch-alls) are excluded from `include`.
